## Questions

1. Which repository surface should own the Codex-specific hook source?

## Findings

### Q1: Which repository surface should own the Codex-specific hook source?

**Answer:** The source belongs under `codex-skills/`, because repository policy
names the provider packages as canonical provider source. The hook set is
machine-local and should remain outside the ready-package install manifest until
it is generalized beyond DevHome and the Remember bridge.

**Evidence:**

- `AGENTS.md:21-26` defines `codex-skills/` and `claude-skills/` as the canonical
  provider package sources and requires package documentation and tests to stay
  aligned.
- `docs/reviews/review-2026-08-09-ai-skills-current-use-audit.md:52-54` retains
  machine-local material as source-only instead of exporting it as portable
  package content.

**Implications:**

- Use a clearly named source-only directory under `codex-skills/`.
- Do not add this machine-bound package to `release-manifest.json` or the Codex
  ready-package install manifest.

### Q2: What is the current repository and branch state?

**Answer:** `main` is five commits ahead of `origin/main`, with one unrelated
working-tree deletion. That deletion must be preserved and excluded from this
migration.

**Evidence:**

- `git status --short --branch` reports `main...origin/main [ahead 5]` and
  `D docs/reviews/review-2026-06-25-gemini-adapter-crosspoll.md`.
- `git log --oneline --reverse origin/main..HEAD` lists the five local commits
  from `2ac9dac` through `1036ee8`.

**Implications:**

- Add only new hook-authority files and intentional documentation changes.
- Do not restore, stage, commit, or otherwise reinterpret the existing deletion.

### Q3: How does this repository distinguish source authority from installed state?

**Answer:** Installed Codex roots are projections. Source-controlled files must
be deployed explicitly into `D:\DevHome\state\codex`; the runtime copy must not
be treated as the canonical implementation.

**Evidence:**

- `docs/reviews/review-2026-08-09-ai-skills-current-use-audit.md:23-24` states
  that installed/live roots are projections rather than source authority.
- `scripts/Install-AgentSkills.ps1:100-113` discovers the DevHome Codex state
  target, and lines 195-224 implement explicit manifest-directory copying.

**Implications:**

- Add a dedicated installer/checker for lifecycle hooks instead of pointing
  Codex directly into a mutable Git checkout.
- Installation must not manufacture hook trust; changed definitions remain
  subject to Codex `/hooks` review.

### Q4: What is the smallest safe migration surface?

**Answer:** Move the exact source scripts, hook definition, and both regression
suites into one source-only package, add an idempotent install/check script, and
document the source/runtime boundary. Generated bytecode and adapter runtime
state stay out of Git.

**Evidence:**

- The installed source consists of `hooks.json`, four hook scripts, one Pester
  suite, and one Python unittest suite under `D:\DevHome\state\codex`.
- `.gitignore` already excludes `__pycache__/`, `*.pyc`, `.tmp/`, and live
  `.codex/` state.

**Implications:**

- The installer should copy only an explicit closed set of owned files.
- A `-Check` mode should prove source/runtime equality without mutating either
  surface.

### Q5: Which verification commands govern the changed repository surface?

**Answer:** Run the hook-specific Pester and Python suites, installer smoke and
drift checks, then the repository release-readiness command and diff review.

**Evidence:**

- `scripts/Test-ReleaseReadiness.ps1:30-67` defines ready-package validation,
  README count checking, provider contract tests, parity reporting, and Git
  whitespace checks.
- `README.md:25-31` names `Test-ReleaseReadiness.ps1` as the release checklist.

**Implications:**

- Hook tests cover the new source-only package; release readiness proves the
  addition did not disturb portable provider packages.

## Cross-Cutting Analysis

### Constraints

- The package is intentionally specific to verified controller `snd-desk` and
  the DevHome Codex root. Machine-sensitive installation must use the installed,
  hash-bound DevMesh v2 verifier rather than the legacy shared compatibility
  verifier.
- The Remember bridge depends on the installed Claude Remember plugin, Git
  Bash, Python, and the local Claude executable.
- Codex trust is user-reviewed state and must not be generated by the installer.

### Risks

| Risk | Likelihood | Impact | Notes |
|---|---|---|---|
| Runtime/source drift | Medium | High | Mitigate with an explicit `-Check` mode. |
| Overwriting unrelated hooks | Low | High | Copy only the package-owned closed set and back up replaced files. |
| Accidental portable export | Medium | Medium | Keep the package out of both release and install manifests. |
| Mixing the existing deletion | Medium | Medium | Preserve and report it separately. |
